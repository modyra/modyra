A multiselect says when a quantity settles, and when a value moves

Two more of the sentences the contract composes and this renderer was not saying. A quantity that
settles names the value and where it now stands, and says separately when it is at its floor —
the register's diagnostic quotes that boundary directly: *the quantity is at its floor and the
control says "" — nothing marks the boundary*. Nothing is said for a quantity that reached zero: the
value is gone, and its removal has its own sentence and its own way back.

The three policies are asked in an order, so they never speak over each other about one act: a
selection that changed is a selection sentence; the same values in a different order is a move; the
same values in the same order with a different count is a quantity.

**The move half is wired and not asserted in this package's bench**, which is said here rather than
left to be found. The contract's gesture for it is `ArrowRight` on a chip with the panel closed, and
that needs the roving focus a real page gives; this fixture dispatches a key at an element without it
and nothing moves. A first version pressed the handle beside the chip instead and **passed** — the
sentence for a selection change is already wired and satisfied "something new was said", one door
answering for another. It is left to the browser tier, which drives real focus.
