A number's declared name reaches the box, and a chip's steppers speak the document's language

Two defects, both found by writing down a rule rather than by a check.

**The name a document declares for a number field was announced to nobody.** The shell names "the
element that stands for the field", and which element that is depends on what the kind hands over. A
text box hands over its input, so the name lands. A number hands over the spinner's container — an
input with a stepper either side — which is neither operable nor role-bearing, so the fallback chain
reached its last branch and named **the container**: a `<span>` with no role, not focusable, never
announced. The document declared a name, a `<span>` nothing could reach carried the words, and the
box a person lands on had none.

It survived because no check in any tier asks a *number* for its declared name — the one row that
asks mounts a text field, and one kind stood for the whole class. The bench now sweeps all eight
natively labelled kinds, and reads the **resolved** name of the element the caption points at:
asking "does some element carry the words" is exactly what made this invisible.

The shell now prefers the one operable that is not a button. A stepper is an action with a name of
its own saying what pressing it does; the box beside it is the field.

**A chip's steppers were named in English on every page.** They were built with the literals
`"Decrease"` and `"Increase"`, so no translation could reach them — and they were the wrong words
besides: the message table says "One fewer" and "One more", which name the act rather than a
direction, and the other renderer already composes those with the option's label. The number field
ten files away reads its own steppers from that same table, so one package was answering one question
two ways.

Measured under a declared locale: `"Uno in meno Alpha"`, where it read `"Decrease Alpha"` before.
