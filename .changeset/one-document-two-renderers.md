The Lit demo draws the checkout its backend defined

The same document the plain demo draws, from the same Rust service, drawn by Lit's own elements.
Nothing in either page knows what a checkout is: the section asks `mdyLitTagFor` which element draws
each kind the document names and hands it the field handle.

Parsed strictly before an element is created, and the document's rules applied to the form — a
condition parsed and never applied is a form that looks obeyed while every rule in it is inert.

A kind Lit draws nothing for is said rather than skipped: a document naming one would otherwise lose
a field with nobody told. When the API is not answering the section says which command starts it.
